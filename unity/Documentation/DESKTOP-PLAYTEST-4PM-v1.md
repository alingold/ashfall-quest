Each module implements IDesktopPlaytestModule.Initialize(context) on a root-created active GameObject. Use real neutral PlayerInput/Locomotion with explicit local single-player fixtures and actual CharacterController physical feedback; no network/authority or XR claims. Input is installed Input System keyboard/mouse. WASD, mouse look, Space jump, Shift sprint, Escape cursor/pause. Clear instructions and safe mouse release are mandatory.

Combat reads View/PlayerRoot/Targets and owns CombatStatus, Hits and RemainingTargets; use actual supported WeaponHandling and Combat/Health interfaces for the local sandbox, with explicitly local test entitlement. It never moves the pawn, mutates original module code, or enables unsupported prepared-fire/ownership transitions. Prefer reliable bounded rifle fire/reload and target response to breadth. Unsupported flow fails visibly. Construction reads the same ray/inputs, owns ConstructionStatus and its own primitive panels/charge state, and uses the real prepared ConstructionCandidate/BuildChargeLedger APIs if viable. It must preserve actual source boundaries and may disable with an explicit reason.

Hud is a passive desktop view over these fields. It can invoke context.RequestReset() and RequestQuit(), and must show controls, paused/cursor state, local-sandbox label and concrete enabled/disabled features. No target/world/pawn mutation. Root or event subscribers own reset; reconnect/restore is not simulated by reset. All modules unsubscribe/clean up their own resources. This context is a local playtest composition surface, never a new shared game protocol, production authentication or source-content approval service.

Each owner stages actual API compile/unit checks and a callable native fixture. Root alone runs imports/builds/native/launch through the shared engine mutex. Deliver promptly with exact dependencies; document cuts rather than wait on sibling outputs or expand scope.
