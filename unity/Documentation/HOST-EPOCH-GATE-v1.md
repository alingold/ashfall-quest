# Host epoch gate v1 — frozen implementation target

Root-owned session/actor/epoch/content and canonical connection provisioning remain authoritative. A new concrete HostEpochAuthority may supply privately constructed IAuthorityGate facets to actual module factories, with one serialized host lane, immutable binding and registry identity, monotonic revision and retained epoch tombstones. No caller-supplied bool/callback or client command can report global quiescence. Factory registration binds real participant objects and exact source profiles; caller inventories or arbitrary successful implementations do not establish coverage.

Ingress closure must immediately reject old-epoch new commands through every registered gate, and stay closed across physical checkpoint reopen. Existing replay/logical receipt histories must survive. New service objects/authority are not published until the entire typed checkpoint and participant set are reconstructed in quarantine. Direct previously captured module references are part of the threat/test boundary. Legacy prepared tokens can bypass a later admission gate if their no-fail commit was already validated; global retirement therefore additionally requires actual owner reservation accounting and drain/abort disposition. A gate alone is not global retirement.

Prepare global retirement binds exact registry revision, old/new session epoch/source binding, canonical connections/lives, checkpoint digest/generation/Health sequence/ACK prefix, bounded expiry and every pending Health, Session, Inventory, weapon, consumable, projectile, stamina and runtime operation. Actual source checkpoints/owner reservation registries must prove absence or reconciliation, under the same lane. Validate catches intervening identities/receipt/producer mutations. CommitValidated makes no external call, allocation, IO or validation; durable intent is flushed before it, and cuts before/after each publication have idempotent recovery with a retained old-epoch tombstone. Unsupported/unregistered participants or untracked legacy tokens must return an explicit blocker and no global-success receipt.

The first implementation may demonstrate an exactly declared subset of concrete factories/admission gates and persisted ingress closure, but must label that subset and continue rejecting global retirement until coverage is real. Do not wrap a void RetireWeapon API as successful receipt. Provide typed exact adoption/producer hooks and tests with actual public modules, retained references, prepared-token bypass attempts, cold subprocesses and acknowledged-prefix pressure. New code does not alter Core, accepted modules, project settings or other owners' files. Root will review/integrate the concrete registry; this document itself grants no runtime approval.
